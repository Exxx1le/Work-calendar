# Облачный календарь отпусков — инструкция по публикации

Комплект сохраняет текущий интерфейс календаря, но вместо прямой записи в CSV использует общую базу Cloudflare D1. Сотрудникам не нужно создавать аккаунты или входить в систему. После публикации любой, кто знает адрес сайта, сможет просматривать и изменять календарь — передавайте ссылку только тем, кому она нужна.

## Что входит в комплект

- `public/index.html` — интерфейс календаря с двумя основными действиями: «Сохранить» и «Выгрузить CSV».
- `functions/api/data.js` — API загрузки и сохранения.
- `schema.sql` — создание таблицы в базе.

## Шаг 1. Создайте базу D1

1. Откройте [Cloudflare Dashboard](https://dash.cloudflare.com/) и войдите в свой аккаунт.
2. Перейдите в **Storage & databases → D1 SQL Database** (название раздела может немного отличаться).
3. Нажмите **Create database**, назовите базу, например `vacation-calendar`, и создайте её.
4. Откройте созданную базу, найдите **Console / SQL Console**.
5. Откройте файл `schema.sql` из комплекта, скопируйте весь его текст в SQL-консоль и выполните запрос.

## Шаг 2. Загрузите комплект в GitHub

Cloudflare Pages Functions нельзя опубликовать обычной загрузкой ZIP через Direct Upload. Для этого комплекта проще всего подключить GitHub-репозиторий.

1. Откройте [GitHub](https://github.com/) и создайте новый репозиторий, например `vacation-calendar`. Для внутреннего корпоративного календаря разумно выбрать **Private**; сам сайт после публикации всё равно будет доступен по URL без входа.
2. Распакуйте ZIP на компьютере.
3. Загрузите в корень репозитория папку `public`, папку `functions` и файл `schema.sql`. Структура репозитория должна быть такой:

   ```text
   public/
     index.html
   functions/
     api/
       data.js
   schema.sql
   ```

   Важно: папка `functions` должна быть в корне репозитория, рядом с `public`, а не внутри `public`.
4. Сделайте Commit / сохраните изменения в репозитории.

## Шаг 3. Создайте сайт Cloudflare Pages

1. В Cloudflare Dashboard откройте **Workers & Pages**.
2. Выберите **Create application → Pages → Connect to Git** (варианты названий могут меняться).
3. Подключите GitHub, выберите репозиторий `vacation-calendar`.
4. В настройках сборки укажите:
   - **Framework preset:** `None` / `No framework`;
   - **Build command:** оставить пустым;
   - **Build output directory:** `public`;
   - **Root directory:** корень репозитория.
5. Нажмите **Save and Deploy**. Если первая публикация завершится успешно, Cloudflare покажет адрес вида `https://название.pages.dev`.

## Шаг 4. Подключите базу к сайту

1. В **Workers & Pages** откройте созданный Pages-проект.
2. Перейдите в **Settings → Bindings**.
3. Нажмите **Add → D1 database**.
4. В поле **Variable name** укажите строго `DB` (именно это имя использует код).
5. Выберите базу `vacation-calendar` и сохраните настройку.
6. Повторно запустите деплой: откройте **Deployments** и нажмите **Retry deployment** у последнего деплоя либо сделайте пустой commit в GitHub. Привязка начинает действовать после нового деплоя.

Официальная справка Cloudflare: [Pages Functions](https://developers.cloudflare.com/pages/functions/get-started/) и [Bindings / D1](https://developers.cloudflare.com/pages/functions/bindings/).

## Шаг 5. Проверьте работу

1. Откройте адрес `https://название.pages.dev`.
2. Статус должен сообщить, что данные загружены из общей базы.
3. Добавьте тестового пользователя, отметьте несколько дат и нажмите **Сохранить изменения**.
4. Откройте сайт в другом браузере или приватном окне. Нажмите **Обновить данные** — тестовый пользователь и даты должны появиться.
5. Удалите тестовые данные, если они больше не нужны.

## Как будут пользоваться сотрудники

1. Открывают общую ссылку.
2. Выбирают своё имя или добавляют его.
3. Отмечают отпускные даты.
4. Нажимают **Сохранить изменения** и дожидаются подтверждения.
5. Следующий сотрудник открывает календарь или нажимает **Обновить данные**, чтобы увидеть последние сохранённые изменения.

Кнопка **Импорт CSV** позволяет загрузить данные из прежнего CSV в интерфейс. После проверки нажмите **Сохранить изменения**, чтобы записать их в облачную базу. Кнопка **Резервная копия** скачивает CSV из текущего состояния страницы; перед резервным копированием сохраните изменения и при необходимости обновите данные.

## Важные особенности

- Данные сохраняются только после нажатия **Сохранить изменения**.
- Если два человека одновременно редактируют календарь, а затем сохраняют версии по очереди, более позднее сохранение может затереть изменения первого. Вы планировали работу по очереди, поэтому для обычного сценария это приемлемо: сотрудник должен сохранить изменения и дождаться подтверждения, прежде чем передавать работу следующему.
- На экране оставлены только основные действия с данными: «Сохранить» и «Выгрузить CSV»; выбор сотрудника и переключение года сохранены. В меню сотрудников можно добавить имя.
- В календаре при совпадении отпусков теперь отображается заметная метка «2 чел.», «3 чел.» и т. д.; при наведении курсора показываются имена всех сотрудников на этой дате. Это позволяет сразу увидеть пересечения, не полагаясь на смешанный цвет.
- В этой версии нет авторизации: любой, у кого есть ссылка, может менять данные. Не публикуйте ссылку открыто.
- Не удаляйте базу D1: в ней хранится общий календарь. Резервную копию CSV можно скачать из интерфейса.
- Если при открытии видите ошибку API/базы, проверьте, что D1 привязана под именем `DB`, SQL из `schema.sql` выполнен, а после привязки был повторный деплой.
